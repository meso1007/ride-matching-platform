# 要件定義（00-requirements）

ステータス: WIP（機能要件の正常系まで合意済み。異常系・非機能要件・規模見積もりはこれから）

## 機能要件

### ライダー（乗る人）

1. 行き先を入力し、ルートと料金の見積もりを見ることができる
2. 配車をリクエストできる
3. 決まったドライバーの情報（名前・車種・ナンバー・評価）を見ることができる
4. ドライバーの現在地と到着予測時刻を、地図でリアルタイムに見ることができる
5. 配車のステータス（ドライバー決定／迎えに移動中／到着／乗車中／完了）を確認できる
6. 到着後、事前登録した支払い手段で自動決済される
7. ドライバーを評価でき、問題があった場合は通報できる

### ドライバー（運転する人）

1. オンライン／オフラインを切り替え、「今フリーです」という空き状態をシステムに伝えることができる
2. 自分の位置情報を継続的に送信する
3. システムから割り当てられた配車リクエストを受諾／拒否できる
   - ドライバーがライダーを選ぶのではない。割り当てはシステム側が行う（選べるようにすると短距離ばかり選ばれる等、ライダー体験が崩れるため）
4. ピックアップ地点までのナビ（ルート）を見ることができる
5. 到着・乗車開始・完了などのステータスをボタン操作で進めることができる
6. 送迎ごとの報酬と、売上合計を確認できる

### システム（マッチング）

1. ライダーの近くにいるフリーなドライバーを探し、配車を割り当てる
2. 前提：エリア内に一定数のドライバーがいること。ライダーの需要がドライバーの供給を溢れる状態は避ける
   - 需給が崩れた場合の扱い（待たせる／料金を上げる等）は未決定事項

## 未決定・これから決めること

- 異常系：ライダー／ドライバーのキャンセル、ドライバーが拒否した場合、近くにドライバーが見つからない場合、決済が失敗した場合
- 非機能要件：レイテンシ目標、可用性、整合性の要求
- 規模の見積もり：ドライバー数、位置更新の頻度、ピーク時のリクエスト数
